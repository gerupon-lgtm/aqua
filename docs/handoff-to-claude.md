## 3. 最後に修正したこと（v0.14.14）

- 発案者が実画面で選んだアイボリーと金の葉模様を、`board-materials.js`の`drawDrainPan`へ組み込み。元のPNGの透かし・光沢を保ち、SVGの色変換と金縁・葉飾りを加える。器の幅・噴出孔・実管・札の位置は維持した。
- 厚みは口を中心に縦1.14倍。下の配管へ影が触れないよう、画像のぼかしだけを0.15へ抑えた。新たな接続金具や深い器の水位表示を足さない。
- `prepare-diagrams.js`は、器と短い管を本体と同じ関数で生成する。説明の4枚もアイボリーと金の葉模様へ同期。図のPNGはSVG内へ含める。
- [採用・点検・公開記録](reviews/2026-11-03-ivory-leaf-pan.md)を参照。色・装飾の検討へ戻す依頼ではない。

### v0.14.13から維持すること

詳細と証拠は[開始合図・更新・妖精の点検](reviews/2026-11-03-cue-and-update.md)。

- 課題のフラッシュは、面の切り替えから**700ms待ち、2回光る（1回0.7秒・間0.35秒、計1.75秒。v0.15.1・v0.15.2で変更）**。合図中も編集できる。条件カードと札の光だけならSVG全体を作り直さず、押している管を保持する。
- タイトル右上と画面下部の更新は、**表示中より新しい版で、全資材の保存が完了したときだけ**出す。同版・旧版・取得途中・版不明では勧めない。両方から同じ適用処理を呼ぶ。手動確認は「メニュー → 更新を確認」。案内文も準備状態に追従する。
- worker（通信なし起動・更新を担当する処理）とは`AQUA_UPDATE_STATUS`で版と準備状況を確認する。旧画面からの`activate-update`にも対応。同版の画面を表示済みなら、workerの切り替えだけで再読込しない。水の再生中は更新適用と別タブによる再読込を保留する。
- 1面の妖精が出ないのは、面だけの特別処理ではなく、案内の既読記録による。未読では出て、説明を終えると隠れ、「ふりかえり」で戻る。**この仕様は変更していない**。連続プレイで案内を出さない規則も維持している。

## 6. 確認済みの範囲と再開手順

v0.14.14は187テスト・16ファイル、構文53ファイル、出題データの同値検査、65資材のビルドが成功。本体の描画で全199出題・600描画、札と口1131個、状態間754組を点検しエラー0。[GitHub Actions 41612273635](https://github.com/gerupon-lgtm/aqua/actions/runs/41612273635)のbuild・deployも成功した。

公開先の65資材とworkerのハッシュ・種類が確認用ビルドと一致し、公開ソースが`c229b7b`であることを確認。公開画面は390×844と1280×800で同じ採用素材・2つの盤の金の葉模様・最前面の札・ページのはみ出し0を確認した。配信用アプリでは左右の噴水盤へ流して100点、噴水と虹、高い器・台座、横向きも確認。詳細な画像とJSONは上の点検記録の配下。

320×640で未読の案内も出す場合、既存のスクロールなし配置では盤面が小さくなる。この寸法確認を、実機の視認性・指での操作の合格とは扱わない。今回CSS・盤面の表示範囲は変更していない。実機受け入れは引き続きT-12に残る。

v0.14.13で行った更新処理の検証は、実ビルド0.14.12→0.14.13と、版だけ変えた合成0.14.14で確認したもの。100点・最少1回と既読記録の保持、配信元を停止しての再起動を確認済み。今回公開した実物の0.14.14とは検証の時点を分けて読む。実機・聴感の受け入れではない。証拠は[開始合図・更新の記録](reviews/2026-11-03-cue-and-update.md)と、その配下のJSON・画像・ログにある。

再開時は、共有リポジトリの現在の差分と公開版を確認する。v0.14.13の引き継ぎ準備時点で未追跡の作業資料が145件あり、今回の比較記録も追加されている。主に`画面案/`の比較用HTML・JS・記録で、除外された原本画像もある。これらを一括追加・削除せず、必要な変更だけを明示してGitへ追加する。

今回の`画面案/2026-11-03-pan-colour/`は採用までの比較履歴。本番へ入れたのはアイボリー・金縁・金の葉模様であり、他の色や装飾は採用していない。比較ページは採用前の白い盤へ加工する前提なので、採用後の本体へそのまま重ねると色・厚み・装飾を二重に適用する。正式な確認は現行の`renderBoard`と公開アプリで行う。

過去の`localhost:5187/画面案/...`やCodexのローカル作業用コピーを、共有リポジトリの本体と混同しない。以後のプレビューは起動元を確認し、共有リポジトリから`npm.cmd run dev`で起動する。標準は`http://localhost:5173/`。

実装後の基本コマンドは次のとおり。Windowsで負荷がある場合は、全テストを省かず、5ファイル以下・並列度1に分けて実行する。

```powershell
npm.cmd test
npm.cmd run check
npm.cmd run check:challenges
npm.cmd run build
```

版の正典は`package.json`。`app.js`の表示版もそろえ、ビルドの同値検査を通す。機能変更では要件・タスクと対応文書を更新する。資料だけなら版を上げず、コミットに`[skip ci]`を付けて同じアプリ版を再公開しない。

変更の扱いはAGENTS.mdと要件0章のA/B/Cに従う。既に合意されたA/Bの作業について承認を取り直す必要はない。計算・判定・保存保護などの前提は別に扱う。動作と見た目の確認を済ませてからGitHubへ反映し、公開の成功と実画面の確認を分けて記録する。

利用できる場合の補助スキルは、不具合の再現・切り分けに`diagnosing-bugs`、Windowsの長い検証に`resource-safe-test-runs`。スキルの有無より、上記の確認条件と証拠を引き継ぐ。
