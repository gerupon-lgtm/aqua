# アクア・ノーツ データ定義

版：基本設計 v0.1（2026-10-31、2026-11-01 要件定義書 v0.3 に合わせて更新）。正典は要件定義書 v0.3 の第8章。ここではデータの役割と必須項目を決める。項目名・形式の細部は実装時に決めてよい（0章A区分）。ただし C-01（保存を無断で消さない）、C-05（サーバーへ送らない）に触れる変更は不可。

数値はすべて分数で持つ（[処理設計](logic-design.md) 第2章）。保存・ファイルでは `"3/2"` のような文字列にする。

## 1. データ一覧

| ID | データ | 置き場所 | 寿命 |
|---|---|---|---|
| D-01 | 面の定義 | アプリ資材（`src/content/`） | 版ごと |
| D-02 | 出題 | アプリ資材（生成スクリプトの出力） | 版ごと |
| D-03 | 回路の状態（編集中） | メモリ | その面・自由作成を開いている間 |
| D-04 | 計算結果 | メモリ | 次の実行まで |
| D-05 | 実行記録 | メモリ（ファイルへ書き出し可） | 次の実行まで。端末に残さない |
| D-06 | 課題の成績 | 端末の保存領域（localStorage） | 利用者が消すまで |
| D-07 | 自由作成の保存（10枠） | 端末の保存領域 | 利用者が消すまで |
| D-08 | チュートリアルの記録 | 端末の保存領域 | 利用者が消すまで |
| D-09 | 前回の水面の線 | メモリ | その面を遊んでいる間 |
| D-10 | 回路ファイル | 利用者の端末のファイル | 利用者が管理 |
| D-11 | 実行記録ファイル | 利用者の端末のファイル | 利用者が管理 |

## 2. 各データの必須項目

### D-01 面の定義

- 面ID（内部ID）、表示番号、セットID、内容版（変更時に上げる）
- 泉：位置、高さの範囲（出題で変わる）
- グラス：ID、位置、グラスの高さ、サイフォンの入口の高さ（サイフォンがある場合）
- 出口：ID、位置、口の高さ、流れやすさ
- 結べる道：ID、両端、通り道（曲がり角と持ち上げた点の座標）、細さ（または太さを変えられる配管の段ごとの細さ）、サイフォン候補かどうか
- 水門：ID、置かれた道
- 排水口（37〜42面、v0.19.0）：面の定義の `drains: [{ id, tower }]`。段ごとの流れやすさは全面共通（閉・半分 1/2・全開 1）。つなぎ方は `drains: {ID: 'half'|'open'}`（閉は持たない）、つなぎ方の名前では `D1:half` のように後ろに足す。出題の検査では vary の `minDrains`（満点で開ける排水口の下限）を使う
- 総まとめ（49〜54面、v0.21.0）：新しい項目はない。水門の面の出題は、指定量が `{ open, closed }`（開いた状態・閉じた状態）になる。vary の `mustGate`（満点のつなぎ方で水門を閉じると届く量が変わる）
- 泉が2つ（43〜48面、v0.20.0）：面の定義の `spring2: { id: 'T', x, height, label }`（`label` は札と解説の呼び名「左の給水塔」「右の給水塔」）。出題の値に `spring2`（右の給水塔の高さ）。vary の `spring2`（高さの候補）、`bothSprings`（満点が両方の給水塔を使う）、`intoSpring2`（満点で右の給水塔へ水が流れ込む）
- 手押しポンプ（31〜36面、v0.18.0）：サイフォン候補の `pump`（ポンプを置くグラスのID）。出題の検査では `mayBreak`（切れるつなぎ方を含めてよい）と vary の `minPumps`（満点で使うポンプの下限）を使う
- 桶の数の範囲
- 音：目盛りの間隔 s、基準 L0・m0
- 再生の上限時間 T（全面共通の5秒。面の定義には持たせず、`src/ui/visual-timing.js` の `PLAYBACK_LIMIT_MS`。2026-11-04）
- テーマの観点（採点用）

### D-02 出題

- 面ID、出題番号、内容版、系統（満点のつなぎ方が同じ出題のまとまり。抽選に使う）
- その出題の数値（細さ、指定量（水門の面は開いた状態・閉じた状態の両方）、泉の高さ、桶の数）
- 検査結果：満点のつなぎ方、部分点の基準、満点のつなぎ方での各グラスの期待水位
- 生成に使った乱数の種と生成器の版（再現のため）
- 置き場所：`src/content/challenges.js`（生成ファイル。手で書き換えない）。形：`CHALLENGES[面ID] = [{ id: "T7-1", number, baseVersion, family: "A"|"B", values: { spring, thinness: {配管: 細さ}, targets: {出口: 指定量}, buckets? }, expected: { perfectKey, perfectCount, partialKeys, levels: {グラス: 水位} }, seed, generator }]`
- 成績のキーは出題ごと（面ID＋出題番号＋内容版）。面の印は、今の内容版のどの出題かを問わず、いちばん良い成績を使う。13・25面は出題の導入で内容版を2に上げたので、試作の版1の成績は消さずに別の成績として残る

### D-03 回路の状態

- 課題：つないだ道のID、太さの段、排水口の段、呼び水をしたサイフォンのID（そのうちポンプで呼び水をしたID。実行記録の `circuit.pumped`）
- 自由作成：パーツの種類と位置、配管の両端と持ち上げた高さ、太さ、排水口の段、呼び水の状態。v0.22.0 の形は `{ spring: { height }, towers: [{ id, slot, outlet: { height } | null }], pipes: [{ id, a, b, thinness, crest, gate }], primed: [配管ID] }`（`src/logic/free.js`）。グラスは決まった置き場所 slot 0〜2（名前は左から A・B・C）、噴水盤はグラスに1つまで（口の高さは給水塔の高さ未満）、crest は持ち上げた山の高さか null、gate は水門。読み込み時は `validateCircuit` で検査する
- 実行中は変更しない（要件5.3）。自由作成で実行中に排水口を回した場合だけ、排水口の段を更新し、計算をやり直す

### D-04 計算結果

[処理設計](logic-design.md) 4.5 のとおり。水門の面は状態ごとに持つ。

### D-05 実行記録

- 実行に使った回路の状態（D-03の写し）と、面ID・出題番号・内容版
- 計算結果（D-04）。分析用の項目（各配管の両端の水位の差と細さ、各グラスに入る量・出る量の合計）を含む
- サイフォンが切れた順番、計算の繰り返し回数
- 判定と点数
- 画面では分かりやすく見せ、書き出すファイルには上の全項目を入れる（要件6.2、2026-11-01 確定）。発案者が法則を理解するための分析にも使う

### D-06 課題の成績

- キー：面ID＋出題番号＋内容版
- 最高点、達成状況（クリア済みか）
- 低い点数・NGでは上書きしない（C-01）
- 内容版が変わった面は、旧版の成績を残したまま新版と区別する（前作と同じ）
- 【想定】保存日時は持たない（持つ場合は世界標準時のISO 8601で保存し、端末の時刻で表示。不明時は日本時間）

### D-07 自由作成の保存

- 10枠。各枠：名前、回路の状態（D-03の自由作成部分）、保存形式の版
- 結果や途中の状態は含めない
- 満杯時の置き換え先・削除・名前変更は利用者が選び、確認してから行う（前作と同じ、C-01）
- 保存に失敗したら、編集中の内容と以前の保存内容を保ち、再試行と回路ファイル保存を案内する（前作と同じ）

### D-08 チュートリアルの記録

- 完了・スキップ（課題、自由作成、パーツごとの初出説明）
- 保存先：端末の保存領域のキー `aqua-tutorial-v1`。形式 `{ "done": { "T1": true, ... }, "skipped": false, "parts": { "gate": true, ... } }`（done は案内を終えた面のID。練習面は P0、お試しの面は T1〜T6。skipped は「案内をスキップ」を押したか。parts は新しいパーツの初出説明を閉じたパーツ：gate・outlets・adjustable・height・siphon。v0.17.0 で追加し、skipped とは別に扱う。parts のない古い記録は未読の扱い）。読めない・保存できないときは初めての扱いで遊べる（v0.10.0）

### D-08a 遊び方の記録（v0.12.0）

- 保存先：端末の保存領域のキー `aqua-modes-v1`。形式 `{ "fewest": { "T2": 2, ... }, "continuous": { "beginner": 12, ... }, "allClearNg": { "beginner": 3, ... } }`
- fewest：選択プレイで、面ごとのクリアまでの最少の試行回数（F-025）。少ないときだけ置き換える
- continuous：連続プレイで、レベルごとのクリアした面数の最高（F-026）。多いときだけ置き換える。面をクリアするたびに保存する（途中で閉じても残す）
- allClearNg：全面クリアした回の、レベルごとの最少NG。少ないときだけ置き換える（v0.15.0 で追加。ない記録は「まだ全面クリアしていない」扱いで、古い形の記録もそのまま読める）
- 消さない（C-01）。読めない・保存できないときは記録なしの扱いで遊べる

### D-09 前回の水面の線

- グラスごとの前回の水位（その面・出題を遊んでいる間だけ）

### D-10 回路ファイル

- 形式の版、自由作成の回路の状態（D-03）
- 読み込み時に形式と値を検査し、不正なら読み込まず理由を表示する。編集中の回路の扱い（保存して入れ替え／保存せず入れ替え／取り消し）は前作と同じ

### D-11 実行記録ファイル

- D-05の内容を JSON 1つにまとめる（2026-11-01 確定）。数値は分数の文字列（例 `"3/2"`）。形式の版を持つ
- 回路ファイルと用途を分け、読み込みには使わない

### D-12 アプリ資材と版

- 版番号（`package.json` の version が正典）、資材の保持と更新は前作の方式を移す

## 3. 移行

既存データはない。保存形式を変える場合は、旧形式を読める変換を用意し、成績と保存した回路を消さない（C-01）。
