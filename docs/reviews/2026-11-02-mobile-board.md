# v0.14.8 スマホの盤面縮小の修正

発案者がv0.14.7をスマホで操作し「プレイできないぐらい盤面が小さい」と指摘。前版のはみ出し検査は、操作と読みやすさの受け入れを満たしていなかった。今回の明示条件は、プレイはスクロールなし、結果と解説のスクロールは許容、視認性を優先すること。

## 修正

- スマホ縦のプレイ画面を100dvh（ブラウザーの上下枠を除いた表示高さ）へ合わせる。縦スクロール案は取り下げ、公開しない。強制的に画面外の内容を隠す方法は使わない。
- 条件の文字サイズを維持し、繰り返す「クリア条件」の見出しを省く。課題の一文、その下に配管・桶・出題等と操作を置き、空白を削る。凡例は対応と意味を残し34pxへ。画面全体と案内の間隔も整理する。
- 通常の説明は68px、案内のある面は104pxを確保。案内の有無は面の入口か、利用者がふりかえりを開いた時に決め、同じ面の編集・実行・結果で保つ。精霊は縦画面でも52×76で輪郭を保つ。本文・操作ボタンを縮小しない。
- boardViewBoxは、部品のない上空だけを表示範囲から外す。グラス・水位・配管・高さ・接続の座標は変えない。実行前から噴水・虹の上端を含む範囲を決め、結果で倍率を変えない。押下位置は従来のSVG座標変換を使う。画面回転でも描き直す。PCと横画面は元の表示範囲。
- 390×680の1面では、絵の実表示幅は約145→280px。外枠の横幅ではなく、SVG内で実際に描かれる幅を測る。360×740の全30面では最小約302px。全端末で横幅いっぱいになるという意味ではない。

## 検査

- 本番の全198出題と練習面、計199問の満点の描画を点検。水門の前後を含む200描画、33,978要素で、給水塔・グラス・壁・配管・札・器・台座・噴水・虹が上端で切れないことを確認。背景の上空は対象から分ける（foreground-bounds.json）。
- 実アプリで390×680と360×740の全30面、計60画面を操作して測定。ページの縦横のはみ出し0、説明と凡例のはみ出し0（stage-layout.json）。スクロールをCSSで隠した結果ではない。
- 320×640の練習の説明と、360×640、390×680、414×740、844×390、1280×800の表示を点検。管の数字から接続して100点まで進め、同じ面の外枠と表示範囲、結果・解説のスクロールを確認する（app-flow.json）。
- 全164テスト、構文42ファイル、v0.14.8のビルド（通信なし資材57件）が成功。配信元でも公開時に出題の一致検査を行う。

検査用ページと手順は[画面案](../../画面案/2026-11-02-mobile-board/README.md)。スマホ実機の指操作と視認性の受け入れは、PCでの模擬表示と区別し未確認として残す。
