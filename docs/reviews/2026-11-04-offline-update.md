# 通信なし・更新の仕組みを前作に合わせる v0.17.5（2026-11-04）

状態：実装・公開済み。実機での確認は未実施（T-12）。

## 指示と対象

発案者の依頼「T-14とT-09を進めて下さい」のうち、T-09の残りに当たる部分。T-09の検証方法には「前作で起きた更新時のタイムアウトの対策を移したうえで確認」とあるが、v0.17.4 までの worker（`src/pwa/worker.js`）には、この対策が入っていなかった。

v0.17.4 までの worker で分かっていた弱点は、次の4つ。

- 入口のページは、いつも通信を優先していた。通信が遅いと、通信が返るまで画面が開かない。
- 資材の取得に期限がなかった。また、1件でも失敗すると、全件を取り直していた。
- 前の版と中身が同じ画像・書体も、版のたびに取り直していた。
- 切り替えた時点で前の版の保存を消していた。このため、前の版の画面を開いたままの別のタブで、資材が見つからなくなるおそれがあった。

## 変更

前作 prism の worker（0.82.0 の更新タイムアウト対策。前作の `docs/reviews/2026-10-22-update-timeout.md`）に合わせた。画面とのやり取り（`AQUA_UPDATE_STATUS`・`activate-update`）は変えていない。

- ビルドで、資材ごとの照合値（SHA-256）を worker に書き込む。
- **準備**
  - 足りない資材だけを取る。
  - 前の版の保存に照合値が一致する中身があれば、通信せずに使い回す。保存された中身も照合する。
  - 通信は4件ずつ、1件60秒まで。取得した中身も照合し、合わなければ準備失敗とする。失敗しても、前の版と記録は残る。
  - 準備が重なったときは、1回にまとめる。
- **起動**
  - この版の資材がそろっていれば、入口のページも保存した物を使う。
  - そろっていないときだけ通信する。つながらなければ前の版の保存を使い、それもなければ「資材がそろっていません（成績や記録は消えていません）」の案内ページを出す。
- **切り替え**
  - 資材がそろっていない版には切り替えない。
  - 直前の版の保存を1つ残し、それより古い保存を消す。前作は前の版の保存を消さないが、本作は画像が多いため1つに限った。
