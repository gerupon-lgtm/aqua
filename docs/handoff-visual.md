# 見た目の仕上げの引き継ぎ（Claude → Codex）

作成：2026-11-01、アプリ v0.14.1（コミット 310928c）時点。

## 1. なぜ引き継ぐか

見た目（T-13）は、絵を作る Codex と、組み込む Claude の2者で進めてきたが、発案者が両者の間に立つ手間が大きかった。前作「プリズム・ノーツ」でも絵と見た目は Codex が担当したので、**見た目の仕上げは、絵の生成から画面への組み込み・公開まで Codex が一人で行う**（2026-11-01 発案者の判断）。

## 2. 担当の範囲

| 担当 | 範囲 |
|---|---|
| Codex | 見た目のすべて：絵の生成、`public/graphics/`、`src/ui/board.js` の描き方（部品・バッジ・演出）、`src/ui/style.css`、`index.html` の見た目の部分、画面の配置（PC の配置を含む）、ロゴ、`docs/assets*.md`・`docs/screens.md` の見た目の記述 |
| Claude | 見た目以外（計算・判定・出題・モード・記録・チュートリアルの中身など）。Codex が作業している間は、このフォルダで変更・コミットしない |

同じフォルダを共有するので、作業する時間を分ける。始めるときと終わったときは発案者が両者に伝える。

## 3. 守る決まり（必ず読む）

- 作業指示：`AGENTS.md`（変更禁止事項、版の管理、文書の同期）。言葉は発案者向けにやさしい日本語で
- 公開：変更のたびに GitHub の main へ送り、Pages での公開まで確かめる（発案者はスマホで確認している）。手順は 6章
- 版：`package.json` の version と `src/ui/app.js` の `APP_VERSION` を同じ値に上げる（修正は z、機能は y）。ビルドが一致を検査する
- コミット：自分が変えたファイルを名指しで add する（`git add -A` を使わない）。`git -c safe.directory=*` を付ける。メッセージの最後に共同作者の行を付ける
- 絵の候補の原本・比較画像は手元だけ（`.gitignore` 済み）。採用した絵は `scripts/prepare-art.py` の形で配信用に縮める（通信なしで使う資材に入るため、軽くする）。候補（`public/graphics/candidates-*`）は配信するが、通信なしの資材には入らない
- 盤面の大きさは、面・状態によって変えない（条件の欄は全部の面で一番高いものにそろえている：`fitConditionHeight`）
- 文字は言葉の途中で折り返さない（`word-break: auto-phrase`）。1行に収まるものを無理に折り返さない
- ボタンの位置は、結果のクリアと NG でそろえる（「次へ」は右端。ないときも場所を空ける）

## 7. Codex作業後の機能担当への引き継ぎ（v0.14.2）

発案者と実際の描画を見ながら、最初の4項目（結果・土・噴水と虹・空の器）と、太さ表示・給水塔の呼び名を調整した。v0.14.1の名札や色調整は採用の前提にしていない。[変更と点検の記録](reviews/2026-11-01-visual-finish.md)。

- 器は固定幅62、中心は接続元のグラス中心+26（board.jsのbasinPlacement）。面ごとの伸縮はない。グラス左12を底まで見せる。高い出口は既存のdyで上下する。台座でも左の水位を隠さない。
- 白い陶器の枠とガラスの内器。前面と奥側の目盛りは湾曲。必要量は淡い金色。量0なら水を塗らない。
- 出口管はグラスから伸びる細い固定幅。計算のサイズは直線の引き出し先の丸い太・中・細で示す。配管を器の上へ立ち上げる案は発案者が不採用とし撤回。高さやつながりはゲームの意味なので、見えやすさだけで取り回しを変えない。
- 地中の管は同じ段・高さを維持し、グラスへの取り付け位置だけを分けて縦の重なりを解消。表示とpipeAtは同じpipePathを使う。通常の太さバッジは管を全て描いた最後に置く。
- renderBoard(svg,model)の呼び出し方、計算・採点・音・保存・モードの操作条件は維持。app.jsの変更は表示用の文言と結果HTML。新しいパッケージ、保存項目、通信は追加していない。
- 比較用の画面案/2026-11-01-実装確認/index.htmlは本番の描画・検査済み出題・実計算を使う手元の確認用。低い水位の例も実際のつなぎ方から選んでいる。生成画像に見た目を似せるだけの確認ではない。

持ち越しはPC専用配置、作品・シリーズのロゴ、開始時の条件演出、説明の挿絵など。自由作成等の機能は今回の見た目の修正に混ぜていない。実機の見え方・聴感の受け入れは未実施。
